# Voice ledger integration

Server only. `createVoiceLedger()` uses the existing uncached service-role Supabase wrapper. Migration 093 must be applied before admitting paid calls. No tenant is seeded: explicitly configure `v2.voice_tenants` with either an internal demo ID or a verified customer/project pair, limits, daily USD ceiling and per-call USD reservation. Disabled is the default. The reservation should cover the configured maximum conversation duration and backend allowance; the owner must stop when measured cost approaches that reservation. The database reserves money but cannot terminate an external provider itself.

1. Generate an owner UUID on the server. `reserve({tenantId,ownerToken,environment,configVersion,datasetVersion,models,testRunId?,scenarioId?})` must succeed before any paid create. Models must be the actual selected `gpt-live-1` / `gpt-5.6-terra` / `willow` configuration. Admission errors fail closed. Never automatically retry a timed-out reservation.
2. `markCreating({sessionId:row.id,ownerToken})` **before** provider HTTP create, then `bindProvider({...owned,providerSessionId})`. A create network failure or malformed success is ambiguous, even if no provider ID was returned.
3. Heartbeat every ~20 seconds (leases last 60 seconds), respect `deadline_at`, and leave time for closure. Checkpoint `recordVoiceUsage({...owned,seconds})` and `recordUsageEvent({...owned,responseId,model,usage})`. Await ingestion before confirming final evidence. Return values contain current `known_cost_usd`, `reservation_usd` and accounting status. Keep owner UUIDs server-side; they fence control and accounting mutations.
4. `finalize({...owned,terminationReason,providerClosed,finalUsageConfirmed})`. `providerClosed` requires authoritative closed evidence / successful hangup. Hangup alone does not prove final usage. `finalUsageConfirmed` requires final cumulative voice and all backend response evidence. Only use `neverCreated:true` in reserved/creating when the server knows no provider request was attempted (track a separate attempted flag set synchronously immediately before the provider call), or `creationRejected:true` after a definitive provider HTTP rejection in creating state. Neither flag is valid for a timeout, disconnect, or unknown create result.
5. Authenticated recovery calls `claimStaleRecoveries({ownerToken:newUUID,limit:10})`. Expired untouched reservations are atomically closed as zero-cost before any recovery claims. Potentially paid claims atomically replace owner tokens; old owners cannot mutate. Within the 60-second recovery lease, terminate known providers and finalize. Unknown provider identities become unresolved. Do not pretend they are free or automatically retry paid creation. Reclaims occur after the unresolved retry lease (5 minutes).

Session rows carry immutable identity/configuration/rate snapshots. Backend response IDs are unique per session; duplicates never change totals. Voice checkpoints take a maximum, never a sum. Only allowlisted numeric usage is stored; no transcript, SDP, provider response body or client secret is accepted into the ledger. Malformed evidence and unknown tariffs stay incomplete. Terra inputs above 272,000 tokens have an unverified tariff and never use the base price. Tariffs are estimated USD against published rates, not invoice reconciliation. Platform fixed costs are outside this ledger.

Accounting is `provisional` while active, `complete` only with provider closure plus final units and known rates, otherwise `incomplete`. Closed sessions may receive late usage evidence without reopening control. Incomplete rows keep at least their original USD reservation against every later admission, including beyond the rolling 24-hour window. Active/unresolved sessions also retain concurrency slots. Confirmed completed costs count against the rolling 24-hour spend ceiling. This intentionally requires operator reconciliation when final evidence is unrecoverable.

## Evidence

`npx vitest run lib/live/usage.test.ts lib/live/metering/index.test.ts` verifies arithmetic, strict parsing, allowlisted payloads, fail-closed service errors, control validation and finalization flags.

The standalone `verify-migration.mjs` runs migration and lifecycle checks against disposable PostgreSQL/WASM. Install `@electric-sql/pglite` into a temporary directory (not the application), then set `PGLITE_MODULE` to its absolute `dist/index.js` path and run `node lib/live/metering/verify-migration.mjs`. It verifies actual SQL behavior, but does **not** prove concurrent remote connections, production grants or provider behavior. Before release, apply the migration to Supabase and verify grants, competing reservations/recovery claims from separate connections, persistent reads and fail-closed outage behavior there.
