# Operator conversation costs

**Known tariff limitation (2026-09-17):** the first real OpenAI comparison confirmed that v1 omits the cache-write premium. `complete`/`reconciles` currently indicate internal ledger evidence, not invoice alignment. See [live findings and required correction](openai-reconciliation.md#first-authenticated-comparison--2026-09-17). Do not use these estimates as final customer billing.

Run from the repository root with `.env.local` containing `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`. The CLI uses the existing uncached server wrapper. Migrations 093–095 must be applied. This is a local operator tool; no public route or `ADMIN_ENABLED` gate is involved. Never distribute the service-role key to demo visitors.

```sh
npx tsx scripts/voice-costs.ts --project nyhavna-utvikling_nyhavna --purpose public --environment production --format json > voice-costs.json
npx tsx scripts/voice-costs.ts --test-run RUN_ID --format csv > voice-costs.csv
npx tsx scripts/voice-costs.ts --customer nyhavna-utvikling --format json
npx tsx scripts/voice-costs.ts --purpose legacy --format json
```

Run `--help` for all filters. Filters combine with AND; `--project` takes the canonical database project ID, not its public URL slug. `--purpose` accepts `public`, `internal`, `benchmark` or `legacy`. Legacy means the historical purpose is NULL: it does not reclassify old demo sessions as customer use. Purpose is independent of customer/project identity. JSON includes individual sessions and component totals, complete sample counts, median, nearest-rank p95 and maximum. Each statistical group has its own tenant/customer/project/purpose/internal demo, environment, test run and scenario. Synthetic runs and customer observations never share an implicit average. Provisional and incomplete counts and known lower-bound costs are separate and excluded from all complete statistics. Empty distributions use null statistics. CSV contains the individual rows for export, including purpose; use JSON for summary statistics and operational limits. All CSV fields are quoted and spreadsheet formula prefixes are neutralized.

`selectedTotals` summarizes only the filtered rows, once for the whole selection (`platform`), then per customer and project. `unattributed` explicitly covers historical rows without customer/project identity. These are overlapping views of the same sessions: never add platform, customer and project totals together. With an unmatched filter, selected counts/costs are zero and the customer/project lists are empty.

`operational` is a **separate, mandatory unfiltered read** of the authoritative ledger and admission policies. It includes every purpose and environment, even when the selected usage is public-only or empty. It does not fan out to usage events or export ownership capabilities. For platform, customer and project scopes it reports:

- Active calls: every state other than `closed`, regardless of age.
- Hour/day attempts: every session created strictly after cutoff minus 1/24 hours, including failed starts.
- Complete cost: persisted known cost for complete sessions created inside the rolling 24-hour window.
- Unresolved exposure: `max(reservation_usd, known_cost_usd)` for every incomplete or provisional session, regardless of age. Reservations and known lower bounds are shown separately for explanation and **must not be added again** to exposure.
- Old incomplete exposure: the portion of unresolved exposure from incomplete sessions outside the 24-hour window. It remains held until accounting is resolved; a closed call does not release it automatically.
- Budget exposure: complete rolling cost plus unresolved exposure. Remaining count slots and USD headroom are clamped at zero.

Status is `warning` at **80%** of any concurrency/hour/day/budget ceiling, `limit_reached` at 100%, `disabled` for a disabled policy and `missing_policy` when no policy exists. Missing policy headroom is unknown (`null`), not unlimited. These are report warnings only; they send no external alerts. Numeric remaining amounts for disabled policies are explanatory, not permission to start. Actual admission also checks all parent and tenant policies and the full reservation for the next call; a budget with positive remaining USD can still refuse that reservation. The report never guarantees the next call will be admitted. The admission calculation uses persisted ledger checkpoints; selected cost rows may conservatively downgrade an inconsistent complete row after comparing its events.

The provider-reported units are voice seconds and backend input/cached/output tokens. Cached tokens are a subset of input, not extra input. USD values are calculated estimates from persisted versioned tariff evidence, not provider invoices. Voice cost uses the session tariff snapshot; backend cost sums persisted deduplicated usage events. Missing evidence or an event/session reconciliation mismatch downgrades an otherwise complete report row to incomplete. Unknown component costs remain unknown; known lower bounds are never presented as final totals. Session duration is wall-clock creation-to-end time, distinct from metered voice seconds. Models, rate/config/dataset versions and termination reason are included. No owner token or transcript is selected or exported.

Reads use an initial UTC cutoff, `created_at <= cutoff` for both selected and operational sessions and `received_at <= cutoff` for events, with stable ascending primary-key cursors. Policies use ordered `(scope_type, scope_id)` pages, advancing by the number actually returned. All reads continue until an empty page, including when the database applies a page cap below 1000. Event reads run in batches of at most ten sessions, retaining output order; any database error aborts without emitting a partial report or scheduling later batches. These separate REST reads are not a transactional snapshot: sessions can receive late usage/finalization and policy configuration can change during export. Reconciliation detects component drift; for repeatable final figures export after the run and its recovery have settled, retaining the cutoff. Reports describe the state observed, not a historical reconstruction as of cutoff. The report reads all ledger history so old liabilities cannot disappear behind a date filter; this is a bounded-concurrency operator export, not a real-time dashboard.

Vercel, Supabase and maps subscriptions/usage are **unmeasured separate operating expenses** here. This report neither fetches those bills nor fabricates a per-call allocation. Provider estimates are not invoices or customer prices; public purpose does not automatically mean billable use. Pricing decisions must add verified billing-period platform expenses and an explicit allocation policy separately. Synthetic benchmark distributions alone do not establish a real customer distribution.
